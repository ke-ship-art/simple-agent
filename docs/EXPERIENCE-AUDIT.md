# 0.2.1 前后端体验审查

日期：2026-10-16。基于现有 0.2.0 原地修复；未升级 pi-ai 或 Electron，保留文档编辑、权限检查和恢复功能。本报告列出能够复现或从调用顺序确认的问题，不声称穷尽所有设备、供应商与故障组合。

## 已确认并修复

| 问题与用户影响 | 修复 |
|---|---|
| 保存仍允许继续输入，旧保存响应会清除后输入的编辑 | 保存期间冻结编辑控件；操作入口同步防重复；支持 Ctrl+S。真实窗口测试在磁盘写入处暂停，验证冻结及恢复 |
| AI 写入开始后用户才输入，原来的未保存检查已经通过 | 在原子替换前再次检查未保存状态；发现编辑即停止，原文件不变 |
| 快速连点或 Enter 可重入；一个操作结束会过早清除其他操作的 busy | 同步操作锁，Enter 遵守相同锁；停止任务独立于普通 UI 操作锁，认证准备阶段也可取消 |
| 切会话/工作区共用聊天输入与引用，可能误发到别的任务 | 草稿及引用按会话隔离；本地持久化，重启可恢复；首次发送认证失败保留输入，准备发送时冻结输入以免被成功回包清空；永久清理会话后移除对应草稿。草稿与聊天历史一样属于本机私密内容 |
| 选择模型就触发凭据解析/刷新；无会话时不能选模型 | 选择只校验模型配置，不联网认证；没有会话时先创建会话，认证延迟到任务开始 |
| 同一上游模型 ID 添加多份配置，可能混用上下文、视觉和输出参数 | 从本轮选中的配置构造请求模型，各份配置独立；增加同 ID 不同能力的回归 |
| 模型设置保存、连接测试与任务启动可能交叉执行 | 主进程设置操作锁；测试可取消；等待期间冻结相关设置，阻止任务启动读取半成品配置 |
| 配置/模型删除或保存失败，内存与磁盘状态可能分离 | 模型新增/编辑/删除、接入删除、会话创建/模型选择、审核标记及任务首条消息的保存失败均回退对应内存状态；接入状态写入失败时保留原凭据 |
| 登录进行中可退出登录；取消替换登录可能影响旧账号 | 登录未完成时拒绝退出；取消后恢复先前凭据；任务启动也检查登录流程是否已结束 |
| OAuth 尚未添加模型时，用通用目录接口测试容易错误报告认证失败 | 订阅接入先报告已读取凭据但尚未验证模型，明确要求添加模型后实际调用，不把凭据存在说成连接成功 |
| 编辑模型后提示“已添加”；模型所属接入改变而上方表单未跟随 | 修改显示“模型修改已保存”；所属接入切换同步表单、目录、待编辑模型与状态；禁止把已有模型 ID 移到另一接入 |
| PDF/Office 切文件残留页码、坐标、输入等局部状态；提取页后页码越界 | 按工作区和文件重新挂载编辑器；PDF 页码随保存结果收敛到有效范围 |
| PDF 文件在检查后被外部修改，图片内容与版本标识不一致 | 页面字节加载及 Agent PDF 读取核对版本，不向模型或编辑器提供混合版本 |
| Excel 直接按 Tab/换行拆分，含引号、多行或 Tab 的单元格错位 | 支持标准 TSV 引号、双引号转义、多行及空单元格；复制采用同样规则；无效引号明确报错 |
| 多次粘贴累计超过保存上限，可能只加入部分修改或直到保存才失败 | 先合并并核对整批操作数，超过 100 项整批拒绝；保留原待保存修改与粘贴内容 |
| Word 允许首 run 样式的勾选不会更新已经输入的修改 | 策略切换同步已有待保存段落操作，保存采用界面实际显示的策略 |
| 旧状态回复覆盖较新流式文本，回答短暂倒退；长聊天持续重绘 | 合并流式文本与状态快照，忽略过时状态请求；Markdown 记忆化，默认显示最近 200 条并支持加载更早内容；用户阅读历史时停止自动拉到底部 |
| 异步文件刷新可能覆盖新打开文件或新输入内容；展开目录不刷新 | 响应返回后再次校验工作区、文档身份和 dirty；文件树只接收最新请求，刷新已展开目录 |
| Diff 切换时旧预览仍可操作新记录；操作错误被模态框遮住 | 预览与修改集 ID 绑定，切换时清空旧结果；操作期间锁定选择，并在审核窗口显示错误 |
| 会话重命名/永久清理失败也关闭对话框；搜索取消可能被当成故障 | 失败时保留输入与错误；搜索按 ID 取消，关闭/卸载清理，正常取消不弹故障；支持带空格的 @ 文件搜索 |
| 恢复警告未显示、聊天不改文件也积累空修改集、缩窄窗口可能挤出聊天区 | 显示恢复警告；完成后移除空修改集；三栏宽度根据窗口可用宽度收敛 |
| Markdown 链接只有外观，无法打开 | 用户点击后通过主进程打开 HTTP(S) 网页；拒绝文件、命令、自定义协议及含凭据 URL |
| 旧配置存在没有所属接入的模型会阻止整个应用启动 | 忽略孤立模型并显示恢复提示，允许重新配置 |

## 验证

- 13 个单元测试文件、100 项测试通过；相比 0.2.0 新增 14 项回归。
- 源码构建的 Electron 验收 20 项全部通过，包含新增 6 项真实窗口场景。
- 便携 EXE 的最终结果见 VERIFICATION.md。测试使用独立数据目录、本机模拟服务和文档副本。
- 首轮回归发现两项测试适配问题：编辑成功提示已更正，旧断言仍预期“添加”；Electron 的 evaluate 环境不支持动态 import，磁盘暂停测试改用 Node 内置模块入口。修正测试后完整重跑通过，没有删除原能力测试。
- 对“没有文件被修改”的旧断言改为检查全部修改集的文件变化为空，兼容不再保留空修改集的行为；检查语义未放宽。

## 仍需实际环境验证

真实 OAuth 账号、供应商权限及用户实际 NAS/WSL2 服务仍需在相应环境验证；模拟服务不能证明所有供应商都兼容。局域网目前支持显式信任的 HTTP 私网地址，私网 HTTPS 仍不开放。高级 Office 格式继续保护，应用不提供 Excel 计算引擎；部分有界 Office/PDF 解析仍在主进程。会话历史与撤销快照长期增长、极端断电及恶意进程持续替换目录不在本轮完整验证范围内。

已有 0.2.0 的数据格式与恢复机制继续兼容；不应让 0.1.x 写入升级后的数据。草稿保存于应用本机浏览器存储，永久清理会话也会清除对应草稿。文件编辑仍需手动保存；突发进程崩溃不保证恢复未保存的文件编辑。应用退出前草稿存储失败会提示，磁盘/存储配额不足时应先复制重要的未发送内容。
